# Feature request: a static-asset copy hook for the design-sync converter

**Filed:** 2026-09-03 · **Repo:** `folio-design-system` (shape: `package`) · **Reporter:** Nan Osborne

Send this to whoever maintains the `design-sync` skill (the source of `.ds-sync/resync.mjs`, `package-build.mjs`, `package-validate.mjs`). It is written to be pasted as-is.

---

## Summary

There is no way to tell the converter "copy this static asset into the bundle verbatim." Any design system whose `cfg.cssEntry` `@import`s a file that isn't itself generated by the build is therefore **structurally unable to produce a passing `resync.mjs` verdict** — not intermittently, but on every single run, forever.

The ask is one config key: `cfg.extraAssets`.

## Reproduction

Any package-shape repo where `cfg.cssEntry` contains a relative `@import` to a vendored file. Ours:

```css
/* tokens/tokens.css — cfg.cssEntry */
@import url("./fontawesome/css/all.min.css");
```

Font Awesome is our icon system, so this import is load-bearing: without it every `<i class="fa-solid …">` in every preview card renders as an empty box.

Run `resync.mjs`. Every time:

```
✗ [CSS_IMPORT_MISSING] _ds_bundle.css @imports "./fontawesome/css/all.min.css"
  which doesn't exist under <repo>/ds-bundle
```

## Root cause

Three facts compose into the failure:

1. **`package-build.mjs` (~line 203)** opens with `rmSync(OUT, { recursive: true, force: true })` and has no preserve list. Everything in `ds-bundle/` is destroyed on every build, so an asset placed there beforehand — or symlinked in — cannot survive.

2. **`package-build.mjs` (~line 384)** appends `cfg.cssEntry` into `_ds_bundle.css` verbatim:
   ```js
   appendFileSync(bundleCss, `\n/* appended from cfg.cssEntry */\n${readFileSync(explicitCss, 'utf8')}`);
   ```
   The `@import` line is carried through unchanged, and the referenced file is never resolved, followed, or copied.

3. **`package-validate.mjs`** then — correctly — fails `[CSS_IMPORT_MISSING]` because the bundle now declares a dependency on a file the build never put there.

So the build emits a CSS file with a dangling import and the validator flags it. Both are behaving reasonably; the gap is that there's no supported way to satisfy the import.

## Why the existing config keys can't cover it

Verified against the vendored scripts on 2026-09-03:

| Key | Why not |
|---|---|
| `cfg.extraAssets` | Does not exist. This is the request. |
| `cfg.extraEntries` | **JS modules only.** Feeds the bundle's export gates and `window.<GLOBAL>` merge (`package-build.mjs` ~255–330, ~501–584). Not a file-copy mechanism. |
| `cfg.extraFonts` | **Extracts `@font-face` blocks and drops everything else.** It cannot carry `all.min.css`, whose value is precisely the `.fa-*` glyph rules it discards. |
| `cfg.replaces` | Could rewrite the `@import` path, but the file still has to exist somewhere under `OUT` — rewriting relocates the problem. |
| `cfg.cssEntry` pointing at a pre-inlined file | Inlining `all.min.css` removes the `@import`, so `[CSS_IMPORT_MISSING]` stops firing — but the `url(../webfonts/…)` references remain, and those are **not** validated. That converts a loud, correct failure into silently broken icons. Strictly worse. |

There is also **no post-build hook** — no `postBuild`, no `cfg.hooks`, nothing between the build and validate stages of `resync.mjs`.

## Why this matters more than "run one extra command"

The extra `cp` is trivial. The damage is to the **verdict**.

`resync.mjs` runs build → diff → validate → capture in one process, and a failed stage stops the chain. So on our repo, on every healthy run:

- `stages.validate.ok` is `false`
- `stages.capture.skipped` is `"prior_failure"` — **capture never runs at all**, so new and contract-changed components silently never get capture sheets and never enter `pendingGrade`
- the top-level `ok` is `false`

The verdict is documented as the CI contract. Ours is a constant. That means:

1. A **real** failure is indistinguishable from the expected one. The signal is gone precisely when it matters.
2. The grading loop is quietly broken — the stage that produces the sheets you're meant to grade never executes.

We worked around it with a local wrapper (`.design-sync/run-resync.mjs`) that treats only `build` and `diff` as authoritative, then does the copy and re-runs validate and capture itself. To keep that cheap it also had to **mirror two of the driver's internal decisions** — the render-check tiering condition and the tier-1 canary pick — because those live inside the stages we skip. That duplication is exactly the kind of thing that rots against skill updates; we pinned the driver's hash and warn on drift, but it shouldn't have to exist.

## Proposed fix

A config key for verbatim copies, resolved relative to the workspace root, bounded by the same containment check as `cssEntry`/`tsconfig`/`extraFonts`:

```jsonc
{
  "extraAssets": [
    { "from": "vendor/fontawesome/css/all.min.css", "to": "fontawesome/css/" },
    { "from": "vendor/fontawesome/webfonts/*.woff2", "to": "fontawesome/webfonts/" }
  ]
}
```

Copied by `package-build.mjs` **after** the `rmSync` and before it writes the sidecar, so the files are present for `package-validate.mjs` and for the render check — which would also mean icons render in preview cards instead of appearing as empty boxes (see the "Font Awesome icons" note in our `NOTES.md`; today they're a permanent known-warning we've had to whitelist).

**Alternative, no new config:** have `package-build.mjs` resolve relative `@import`s in `cfg.cssEntry` and copy the imported file — plus its own relative `url()` references — into the bundle. Strictly more magical, but it makes `cssEntry` self-contained, which is what the current `[CSS_IMPORT_MISSING]` check already assumes.

**Smallest possible mitigation** if neither lands: teach `resync.mjs` to run `cfg.postBuildCmd` between the build and diff stages. One shell-out would remove the need for our entire wrapper.
